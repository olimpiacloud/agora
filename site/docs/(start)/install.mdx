## Requirements

- **Ubuntu or Debian**, x86_64 or arm64, with systemd.
- **Google Chrome or Chromium.**
- **Xvfb.**
- Root access (`sudo`) to install the binary, the `agora` system user and the service.

The installer takes care of all of it: Xvfb, VA-API, Google Chrome (Chromium on arm64) and the system user.

## One-line install

```bash
curl -fsSL https://agora.olimpia.dev/install.sh | sudo sh
```

It downloads the latest release for your architecture and checks its SHA-256 (if the release cannot be found or downloaded it stops with an error; use `--source DIR` to build a local checkout), installs `/usr/local/bin/agora`, creates the unprivileged `agora` user that runs apps and browsers and the `agora-x` user that runs the X servers, and enables the `agora` systemd service. Running it again upgrades in place and restarts the service only if something changed. Read the script first if you prefer: [agora.olimpia.dev/install.sh](https://agora.olimpia.dev/install.sh).

If Claude Code, Codex or Paseo are installed for the user who ran `sudo`, it also registers the Agora MCP server (`agora mcp`), installs the Agora skill and installs the Paseo plugin. The MCP server gets the admin token through `AGORA_TOKEN_FILE=~/.config/agora/token`, a file only that user can read (mode 0600), so the token never appears in a command line or in the agent configs. If an older install registered the server with an inline `AGORA_TOKEN`, running the installer again re-registers it with `AGORA_TOKEN_FILE` and recommends rotating the token.

Pass options after `sh -s --`, for example `curl -fsSL https://agora.olimpia.dev/install.sh | sudo sh -s -- --no-agents`:

| Option | What it does |
| --- | --- |
| `--version vX.Y.Z` | Install this release instead of the latest. |
| `--prefix DIR` | Install under `DIR` instead of `/usr/local`. |
| `--source DIR` | Build from a local checkout instead of downloading. |
| `--no-agents` | Do not configure Claude Code, Codex, the skill or Paseo. |
| `--no-paseo` | Do not install the Paseo plugin. |

Check that the daemon is up and print your admin token:

```bash
systemctl status agora
curl -s http://127.0.0.1:7788/v1/health
sudo agora token
```

:::warning
The admin token gives full control over every workspace. Keep it out of shell history, logs and chats, and hand agents [cursor tokens](/concepts#cursors) instead.
:::

## Open the dashboard

The daemon listens on `127.0.0.1:7788` only. Open `http://127.0.0.1:7788` on the same machine and paste the admin token. From another machine, use an SSH tunnel:

```bash
ssh -L 7788:127.0.0.1:7788 you@your-server
```

For permanent remote access, put Agora behind an authenticated tunnel such as Cloudflare Tunnel with Access. See the [security model](/security).

## Build from source

You need Go, a C toolchain and the x264 and libva headers (Agora encodes H.264 through cgo, with VA-API for GPU encoding when a device is available).

```bash
sudo apt install xvfb libx264-dev libva-dev pkg-config build-essential
git clone https://github.com/olimpiacloud/agora && cd agora
make build
sudo install -m 0755 bin/agora /usr/local/bin/agora
sudo useradd --system --create-home --home-dir /var/lib/agora-apps --shell /usr/sbin/nologin agora
sudo useradd --system --no-create-home --home-dir /nonexistent --shell /usr/sbin/nologin agora-x
sudo cp deploy/agora.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now agora
```

## Run without systemd

`agora serve` runs in the foreground. As root it keeps state in `/var/lib/agora`; as a normal user, in `~/.agora`.

```bash
agora serve --listen 127.0.0.1:7788 --home ~/.agora
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--listen` | `127.0.0.1:7788` | HTTP address. Non-loopback addresses are refused unless `AGORA_ALLOW_PUBLIC=1`. |
| `--home` | `/var/lib/agora` or `~/.agora` | State directory (also `AGORA_HOME`). |
| `--apps-user` | `agora` | Unprivileged user for apps and browsers when running as root. |
| `--x-user` | `agora-x` | Dedicated user for the Xvfb servers when running as root, separate from the apps user so apps cannot touch the X servers. If it does not exist, Agora logs why and runs Xvfb as root. |
| `--sandbox-default` | `true` | Create new workspaces [sandboxed](/security#sandboxed-workspaces). Only the admin can opt out, with `"sandbox": false` in the workspace config. Needs root and an apps user; otherwise Agora logs why at startup and creates them without the sandbox. |
| `--chrome` | auto-detected | Chrome or Chromium binary. |
| `--rtc-port` | `0` | Single UDP port for WebRTC (`0` picks ephemeral ports). |
| `--rtc-interfaces` | all | Comma-separated interfaces for WebRTC candidates. |
| `--rtc-loopback` | `true` | Offer loopback ICE candidates. |
| `--idle-after` | `5m` | Mark a workspace idle after this long without activity. |
| `--suspend-after` | `30m` | Suspend a workspace after this long without agent activity or human input, even if someone is watching (`0` keeps workspaces running). |
| `--tab-idle` | `15m` | Close browser tabs unused for this long and stop apps of cursors that already ended (`0` never closes them). |
| `--cursor-retention` | `168h` | Delete finished cursors with no live descendants after this long (`0` keeps them forever). |
| `--agent-max-runtime` | `0` | Fail and stop a launched agent after this long (`0` sets no limit). A launch can ask for a shorter time with `launch.max_runtime`; only the admin can ask for a longer one. |
| `--max-agents` | `16` | Launched agents (`launch.adapter`) that may be alive at once, across all workspaces. Spawning one more fails until another ends (`0` removes the limit). |
| `--worktree-roots` | empty | Comma-separated absolute directories where cursors may create git worktrees. Empty allows any repository; either way, cursors only get worktrees of repositories whose top-level directory and `.git` are owned by root (the admin is not restricted). |
